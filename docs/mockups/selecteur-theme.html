Pi-Web — sélecteur de thème MOCKUP

Proposition AVANT implémentation : la notion d'« accent » disparaît au profit d'un sélecteur de thème. « Hacker » porte l'identité Pi-Web (packs verts actuels, défaut) ; Violet, Orange, Cyan et Rose restent sélectionnables comme thèmes à part entière. Les couleurs affichées sont celles des packs réels pi-web-<accent>-<mode>.

4 · Notes & points ouverts pour la validation avant implémentation

Ce que le mockup acte

  • « Hacker » = packs verts actuels pi-web-green-dark / pi-web-green-light, marqué DÉFAUT.
  • Les 4 autres accents deviennent des thèmes nommés (Violet, Orange, Cyan, Rose) — option 2 retenue.
  • Déclencheur : pastille + nom du thème ; liste avec aperçu + coche sur la ligne active.
  • Le choix sombre/clair entre dans le panneau ; le toggle Scanlines est conservé.
  • Migration : un accent enregistré est relu comme thème équivalent (vert → Hacker), clé pi-web-accent inchangée.

Points ouverts / limites

  • Libellé du défaut : « Hacker » retenu ici, alternatives « Vert néon » ou « Défaut ».
  • Bouton ☀/☾ du header : supprimé (mode dans le panneau) ou conservé comme raccourci ?
  • Bibliothèque : section repliée, séparée, ou second onglet « plus de thèmes » ?
  • Rendu statique : aucun JS, aucun état, aucun localStorage — les clics ne changent rien (voulu pour la validation visuelle).
  • Les couleurs bibliothèque sont extraites de holaf-tokens.js (getPreset()) ; pas de mini-écran complet pour ces 5 familles.
  • Les mini-écrans sont des reproductions stylisées à taille réduite, pas une capture de l'app réelle.
Mockup autonome (CSS inline, zéro dépendance, zéro requête réseau) — aucun fichier applicatif n'a été modifié. Couleurs Pi-Web : frontend/src/theme/pi-web-theme.ts · couleurs holaf : holaf-lib/js/holaf-tokens.js.
